## 5. 如何接手

### 5.1 环境准备（首次）

```bash
brew services start mariadb && brew services start redis
mysql -u "$USER" -e "CREATE DATABASE IF NOT EXISTS guda_dev CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
cd backend && cp .env.example .env && uv sync && uv run python manage.py migrate && uv run python manage.py init_roles
cd ../frontend && pnpm install
```

`.env` 中 `DB_HOST` 用 `localhost`（MariaDB `unix_socket` 认证只对 localhost 生效）。

### 5.2 日常启停

```bash
./scripts/dev-start.sh    # 后端 8000 + 前端 5173，含探活
./scripts/dev-stop.sh     # 停止脚本启动的进程
```

日志在 `.dev/backend.log`、`.dev/frontend.log`（已 gitignore）。端口或启动命令变更时，改 `scripts/dev-start.sh` 顶部常量即可。

### 5.3 提交前质量闸

```bash
cd backend
uv run ruff check . && uv run ruff format --check .
uv run python manage.py makemigrations --check --dry-run
uv run python manage.py spectacular --file /tmp/schema.yaml --validate
uv run coverage run -m pytest && uv run coverage report

cd ../frontend
pnpm lint && pnpm type-check && pnpm test && pnpm build
```

## 7. 必须沿用的约定

1. 金额一律字符串十进制传输，计算只在后端，前端仅格式化展示。
2. 密码、手机号、地址等敏感字段禁止进日志。
3. 所有 API 错误复用 `apps/common/exceptions.py`，禁止自定义响应体。
4. 业务模型继承 `BaseModel`，对外只用 `public_id`，数据库主键不外露。
5. 生产配置不入仓，全部经 `/srv/guda/env/.env` 注入；缺关键变量启动即失败。
6. 发布走 `publish.sh` + 探活；不做逆向迁移，回滚依赖发布前备份。
7. 每个任务完成后必须在迭代计划对应迭代的验收登记表登记，未登记视为未完成。

## 8. 已知坑（避免重复踩）

| 现象 | 处理 |
| --- | --- |
| `uv sync` 编译 `mysqlclient` 失败 | 设置 `MYSQLCLIENT_CFLAGS` / `MYSQLCLIENT_LDFLAGS` 指向 `/opt/homebrew/opt/mariadb` |
| 数据库认证失败 | `.env` 的 `DB_HOST` 改 `localhost`；备份/恢复脚本已区分 socket 与 TCP |
| `pnpm install` 跳过 esbuild 构建脚本 | 保留 `pnpm-workspace.yaml` 的 `onlyBuiltDependencies` |
| 401 被吞成 403 | 异常处理器已强制还原 401，新增认证类时不要绕过该处理器 |
| macOS bash 3.2 报 `unbound variable` | 脚本统一 `${var}` 写法，空数组用 `${arr[@]+"${arr[@]}"}` |
| 日志轮转冲突 | 使用 `WatchedFileHandler`，轮转交给 logrotate |
