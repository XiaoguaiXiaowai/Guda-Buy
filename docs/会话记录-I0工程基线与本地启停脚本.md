### 3.4 本地开发脚本

| 文件 | 作用 |
| --- | --- |
| `scripts/dev-start.sh` | 一键启动后端 8000 + 前端 5173；前置检查 `.env`、虚拟环境、node_modules；PID/日志写入 `.dev/`；轮询 `/healthz/` 与首页确认就绪；重复执行跳过已运行服务 |
| `scripts/dev-stop.sh` | 按 PID 停止（SIGTERM → 10×0.5s 轮询 → SIGKILL），只处理脚本自身启动的进程；重复执行安全退出 |

```bash
./scripts/dev-start.sh   # 启动 + 健康检查
./scripts/dev-stop.sh    # 停止
```

- 日志：`.dev/backend.log`、`.dev/frontend.log`（`.dev/` 已 gitignore）。
- 后端 `--noreload`、前端直接调 `node_modules/.bin/vite`，保证 PID 即服务进程，停止后无残留子进程。

## 5. 过程中遇到的问题与修复

| # | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 1 | `uv sync` 编译 `mysqlclient` 失败 | 本机缺少 MariaDB 头文件路径 | 显式指定 `MYSQLCLIENT_CFLAGS` / `MYSQLCLIENT_LDFLAGS` |
| 2 | Django 连库报认证失败 | MariaDB `unix_socket` 认证只对 `localhost` 生效 | `.env` 的 `DB_HOST` 改为 `localhost`，并在 `backup/restore` 脚本中区分 socket / TCP |
| 3 | `pnpm install` 跳过 esbuild 等构建脚本 | pnpm 11 默认不执行依赖构建脚本 | 新增 `pnpm-workspace.yaml` 的 `onlyBuiltDependencies`（含 `packages: ['.']` 以保留真实工作区） |
| 4 | Vitest 与 Vite 6 不兼容 | vitest 版本过旧 | 升级至 3.2.4，`defineConfig` 改从 `vitest/config` 引入 |
| 5 | 401 被吞成 403 | 未配置认证类时 DRF 会把 `NotAuthenticated` 改写为 403 | 异常处理器内对 401 类异常强制还原状态码 |
| 6 | 启动脚本在 macOS 报 `unbound variable` | 系统 bash 3.2 在中文全角括号后误判变量名边界 | 统一改为 `${var}` 写法 |
| 7 | 日志文件轮转与 logrotate 冲突 | `TimedRotatingFileHandler` 自带轮转 | 改用 `WatchedFileHandler`，交由 logrotate 处理 |
| 8 | `backup.sh` 在 `set -u` 下报空数组未绑定 | bash 3.2 对空数组展开严格 | 改为 `${arr[@]+"${arr[@]}"}` |

## 6. 关键约定（后续迭代沿用）

1. 金额一律以字符串十进制传输，前端只做展示格式化，优惠计算全部在后端。
2. 密码、手机号、地址等敏感字段禁止写入日志。
3. 所有 API 错误必须复用 `apps/common/exceptions.py` 的统一结构，禁止自定义响应体。
4. 业务模型继承 `BaseModel`，对外一律使用 `public_id`，数据库主键不外露。
5. 生产配置不落库、不入仓，全部经 `/srv/guda/env/.env` 注入；缺关键变量时启动即失败。
6. 发布走 `scripts/publish.sh` + 健康检查；数据库不做逆向迁移，回滚依赖发布前备份。
