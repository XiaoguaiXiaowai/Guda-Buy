## 1. 本迭代交付物

### 1.1 后端

| 模块 | 文件 | 说明 |
| --- | --- | --- |
| 消息模型 | `backend/apps/notifications/models.py` | `Notification`：5 类消息（`ORDER_PAID`/`ORDER_SHIPPED`/`ORDER_CANCELLED`/`COUPON_EXPIRING`/`SYSTEM`）、业务跳转标识、`is_read`/`read_at`、联合索引 |
| 领域服务 | `backend/apps/notifications/services.py` | `create_notification` 唯一写入口；`notify_order_paid/shipped/cancelled`、`notify_coupon_expiring`；通知失败只记日志；`mark_read`（幂等）/`mark_all_read` |
| 查询 | `backend/apps/notifications/selectors.py` | 类型筛选、出参组装、未读数 SQL 计数 |
| 接口 | `backend/apps/notifications/api.py`、`urls.py` | 4 个端点，见下表 |
| 契约 | `backend/apps/notifications/serializers.py` | OpenAPI 出参 |
| 迁移 | `backend/apps/notifications/migrations/0001_initial.py` | `notifications_notifications` 表 |
| 事件接入 | `backend/apps/payments/services.py`、`backend/apps/orders/services.py`、`backend/apps/coupons/tasks.py` | 支付成功、发货、用户取消、超时取消、券到期均通过 `transaction.on_commit` 落消息 |
| 交易汇总 | `backend/apps/orders/selectors.py`、`api.py`、`serializers.py`、`urls.py` | `GET /api/v1/users/me/orders/summary/`：按状态计数与金额汇总、`paid_amount` |

接口清单：

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/v1/notifications/` | JWT | 消息列表，分页 + `type` 筛选 |
| GET | `/api/v1/notifications/unread-count/` | JWT | 未读数（SQL 计数） |
| POST | `/api/v1/notifications/{public_id}/read/` | JWT | 标记单条已读（幂等） |
| POST | `/api/v1/notifications/read-all/` | JWT | 全部已读，返回更新条数 |
| GET | `/api/v1/users/me/orders/summary/` | JWT | 交易记录汇总 |

业务错误码：`NOTIFY_NOT_FOUND`(404)。

`type` 取值：`ORDER_PAID`、`ORDER_SHIPPED`、`ORDER_CANCELLED`、`COUPON_EXPIRING`、`SYSTEM`。

消息生成规则：

- 支付成功 → 标题含订单号，正文含实付金额；发货 → 正文含运单号；取消 → 正文含原因。
- 券到期：同一张用户券只发一条，重复执行任务不会重复提醒；窗口沿用 `COUPON_EXPIRING_DAYS`（默认 3 天）。
- 正文不含手机号、详细地址等敏感信息（有用例断言）。
