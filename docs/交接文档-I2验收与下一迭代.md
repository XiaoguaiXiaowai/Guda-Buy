## 8. 必须沿用的约定

1. 所有写操作只进 `services.py`；视图只做协议转换与权限校验。
2. 商品必须挂**二级分类**；分类只支持两级，删除有子分类或商品的分类返回 `PRODUCT_CATEGORY_NOT_EMPTY`。
3. 上架要求至少 1 个在售 SKU；最后一个在售 SKU 禁止下架（`PRODUCT_STATUS_CONFLICT`）。
4. 库存只允许**正整数增量**，不允许直接覆写；每次调整写 `StockLog` 并记录操作人；超 `stock_capacity` 返回 `PRODUCT_STOCK_INVALID`。
5. 任何商品/分类/SKU 写操作后必须调用 `bump_product_version()` 与 `bump_category_version()`，否则前台缓存不失效。
6. 前台列表/详情只暴露 `ON_SALE` 商品与在售 SKU；对外标识一律用 `public_id`。
7. 错误码保持 `PRODUCT_*` 前缀，统一走 `apps/common/exceptions.py`。
8. 每个任务完成必须在《验收登记表》登记，未登记视为未完成。
9. 价格区间 `price_min/price_max` 由 service 维护，禁止在视图中手改。

## 9. I2 已知坑

| 现象 | 处理 |
| --- | --- |
| 索引名超过 30 字符导致迁移失败 | MySQL 上限 30 字符，SKU 商品索引命名为 `idx_catalog_skus_product`，勿加长 |
| 库存调整接口返回 400 | 只接受 `delta`（正整数）；减库存请用后续 I5 订单锁定/释放逻辑，不要传负数 |
| 修改 SKU 后详情仍旧价格 | 必须走 `services.update_sku`，它内部会 bump 商品版本号；直接 `Sku.save()` 不会失效缓存 |
| 详情反复查库 / 缓存击穿 | 空值缓存 60s + `SET NX` 互斥锁重建，测试需 `autouse` 清 `catalog:*` key |
| 图片上传 400 | 依次校验扩展名 → MIME → 5MB → Pillow 完整性 → 4096px；测试用 `SimpleUploadedFile` 显式给 `content_type` |
| operator 调库存接口 403 | 权限点由迁移创建，组授权由 `init_roles` 写入；新增迁移后必须在目标库重跑 `init_roles` |
| DRF schema 报「could not derive type of queryset」 | 所有 `GenericAPIView` 显式设 `queryset = Product.objects.none()` |
| 分页返回结构不对 | 必须用 `self.paginate_queryset` + `get_paginated_response`，不要手写 count |
| 前端图片 404 | 图片以相对路径缓存，`resolveImageUrl` 拼后端域名；开发环境依赖 Vite `/media` proxy |
| 相关推荐为空 | 同分类在售商品不足 1 个时为正常结果；验收前先确认每个分类至少 2 个在售商品 |
