## 8. 必须沿用的约定

1. 所有写操作只进 `services.py`，视图只做协议转换与权限校验。
2. 敏感字段（密码、手机号、地址）禁止进日志；手机号仅以密文 + 哈希落库。
3. 错误统一走 `apps/common/exceptions.py`，业务码保持 `AUTH_*` / `USER_*` 前缀。
4. 对外只暴露 `public_id`，数据库主键不外露。
5. access 只存前端内存；refresh 只走 HttpOnly Cookie（path `/api/v1/auth/`）。
6. 每个任务完成必须在《验收登记表》登记，未登记视为未完成。

## 9. I1 已知坑

| 现象 | 处理 |
| --- | --- |
| 切换自定义 User 后迁移报 `auth_user` 冲突 | 必须空库重建（drop/create `guda_dev`）再 `migrate` + `init_roles` |
| refresh 接口 403 | 前端必须带 `X-Requested-With: XMLHttpRequest`，且 Origin 在白名单内 |
| 第 5 次错误密码仍返回 401 | 设计如此：第 6 次请求由 throttle 入口返回 423，不要改服务层逻辑 |
| 测试里自定义 throttle scope 报 `ImproperlyConfigured` | `config/settings/test.py` 必须显式保留 `login/register/email_code` 速率 |
| 验证码重复发送 429 | 60 秒重发限制与每日 10 次上限，测试需用不同邮箱 |
| 旧 refresh 重放返回 401 | 属预期（轮换 + 黑名单），登出同样拉黑 refresh 且接口幂等 |
| 头像上传 400 | 依次校验扩展名 → MIME → 5MB → Pillow 完整性 → 4096px，注意 `content_type` 与真实格式一致 |
| MySQL 不支持 partial unique index | 手机号唯一性用 `phone_hash unique=True, null=True` 表达 |
| 索引名超 30 字符 | `idx_acct_addr_user_default` 为 MySQL 上限内命名，勿加长 |
