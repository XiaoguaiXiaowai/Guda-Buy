cd backend && cp .env.example .env && uv sync --group dev
uv run python manage.py migrate && uv run python manage.py init_roles

## 8. 必须沿用的约定

1. 所有 CMS 写操作只进 `apps/cms/services.py`，视图只做协议转换与权限校验。
2. 页面状态只允许 `DRAFT → PUBLISHED → OFFLINE` 与 `OFFLINE → PUBLISHED`；已发布页面必须先下线才能删除。
3. 富文本入库前必须经 `sanitize_html`；禁止在视图或前端绕过清洗直接落库。
4. 任何栏目/页面/轮播/公告写操作后必须 `bump_cms_version()`；商品写操作沿用 `bump_product_version()`，首页 key 依赖两者。
5. 前台页面仅暴露 `PUBLISHED` 且栏目启用的页面；对外标识一律使用 `public_id`，页面路由使用 `slug`。
6. 轮播仅暴露启用且在 `[start_at, end_at]` 内（空值表示不限）；权重倒序。
7. 后台操作写 `logger="guda.cms"` 结构化审计日志，至少包含 `action`、`target`、`operator`。
8. 错误码保持 `CMS_*` 前缀，统一走 `apps/common/exceptions.py`。
9. 每个任务完成必须在《验收登记表》登记，未登记视为未完成。

## 9. I3 已知坑

| 现象 | 处理 |
| --- | --- |
| 富文本编辑器里能输入脚本，保存后消失 | 服务端保存时清洗，属预期；不要为预览绕过清洗 |
| 外链图片保存后消失 | `img src` 仅允许站内相对路径或 `CMS_ALLOWED_IMAGE_HOSTS`（含 `APP_SITE_URL` 主机） |
| 页面发布后仍 404 | 检查页面状态、栏目是否停用、slug 是否一致；缺失结果有 60s 负缓存，但写操作会 bump 版本 |
| 新建轮播后前台不显示 | 轮播需启用、处于时间窗且 `image` 非空；首页只渲染 `HOME_TOP`，`HOME_MIDDLE` 暂无前台区块 |
| 轮播上传 400 | 依次校验扩展名 → MIME → 5MB → Pillow 完整性 → 4096px；测试需显式 `content_type` |
| operator 无法发布 | 存量库需重跑 `init_roles` 补 `cms.publish_page`（组名 operator 亦可通过） |
| 首页缓存不失效 | 商品/分类写操作必须走 catalog service 内部 bump；直接 `save()` 不会失效 |
| 页面删除后 slug 可复用 | 删除时 slug 会被改写为 `{原slug}-del-{id前缀}`，因此可重新创建同 slug |
| 日期时间差 8 小时 | 前端 `value-format="YYYY-MM-DDTHH:mm:ss"` 不带时区，DRF 按 `Asia/Shanghai` 解释；需要绝对时间时补 `+08:00` |
| 日志里看不到 `extra` 字段 | 审计信息在 message 中，`grep 'action=cms.'` 即可 |
